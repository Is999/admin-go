# 运行配置管理接口

## 范围

本接口只管理运行期会随业务增加的大列表配置：

- `task_periodic`
- `archive_jobs`

`workflows.user_tag` 等单一小配置仍由 YAML 管理。周期任务和归档任务不再从 `runtime.yaml` 读取；数据库模式首次启动只发布初始化资产写入草稿表的数据，草稿为空时拒绝启动，不使用文件列表回退。多个实例同时首启时共用 `runtime_config_state` 行锁：只有第一个取得锁且确认 active 仍为空的实例创建初始版本，后续实例加载已发布版本，不会生成重复 release。

## 权限与 MFA

| 权限码 | 说明 |
| --- | --- |
| `200050` | 运行配置页面入口 |
| `200051` | 列表、发布历史和快照查询 |
| `200071` | 查询运行配置概览 |
| `200052` | 保存、删除周期任务和归档任务草稿 |
| `200053` | 预检草稿 |
| `200054` | 发布草稿 |
| `200055` | 回滚发布 |

发布和回滚必须携带 MFA 二次票据，场景号为 `12`。

## 接口列表

### 查询概览

```http
GET /api/runtime-config/overview
```

默认只返回当前来源、运行环境、active 版本和草稿数量，不读取或序列化全量列表。快照对比页显式请求 `GET /api/runtime-config/overview?includeSnapshots=true` 时，才返回当前运行态快照和全量草稿快照；周期任务与归档任务各可达一万条，普通页面刷新禁止携带该参数。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `currentSnapshot` | `includeSnapshots=true` 时返回当前运行态快照，仅包含 `archive_jobs` 与 `task_periodic`；默认为空列表。 |
| `draftSnapshot` | `includeSnapshots=true` 时从全量草稿表生成，排序和发布快照一致；默认为空列表。 |
| `draftChecksum` | `includeSnapshots=true` 时返回草稿快照 SHA256，与预检和发布口径一致；默认空字符串。 |
| `draftChanged` | `includeSnapshots=true` 时表示草稿 checksum 是否不同于当前 active checksum；默认 `false`，不得在未请求快照时用于判断差异。 |

### 周期任务草稿

```http
GET /api/runtime-config/periodic?page=1&pageSize=20
POST /api/runtime-config/periodic
DELETE /api/runtime-config/periodic/:id
```

查询支持 `keyword`、`workflow`、`enabled`；`pageSize` 默认 `10`、最大 `500`，前端提供 `10/20/50/100/200/500` 六档。保存字段对应 `task_periodic` 单项配置，`cron` 与 `everySeconds` 二选一；`enabled` 省略时默认启用，显式 `false` 才关闭。`retry` 最大为 `25`，`timeoutSeconds` 最大为 `86400`，`shardTotal` 最大为 `128`；三者填 `0` 时使用对应默认值。

周期任务草稿和发布快照最多 `10000` 条。新增第 `10001` 条时返回参数错误；预检、发布、回滚及首次启动发现快照越界时拒绝整次操作，不截断列表，也不会先清空已有草稿。

### 归档任务草稿

```http
GET /api/runtime-config/archive-jobs?page=1&pageSize=20
GET /api/runtime-config/archive-jobs/:id/progress
POST /api/runtime-config/archive-jobs
DELETE /api/runtime-config/archive-jobs/:id
```

查询支持 `keyword`、`database`、`enabled`；`pageSize` 默认 `10`、最大 `500`，前端提供 `10/20/50/100/200/500` 六档。保存字段对应 `archive_jobs` 单项配置。

归档任务草稿和发布快照最多 `10000` 条。新增第 `10001` 条时返回参数错误；预检、发布、回滚及首次启动发现快照越界时拒绝整次操作，不截断列表，也不会先清空已有草稿。

数量上限之外，发布口径生成的 JSON 和 YAML 单份快照均不得超过 `15728640` 字节（15 MiB）。该边界低于 `runtime_config_release.snapshot_yaml` 的 MySQL `MEDIUMTEXT` 上限，并限制 table-cache 回源 Redis 时的单值体积；字段内容导致快照超限时，预检或发布返回明确错误，不写入截断数据。

#### 查询归档任务执行详情

执行详情按草稿 ID 读取任务名，再查询当前实例主库中的 `archive_watermark` 和 `archive_segment` 控制表。接口不会统计业务热表总行数，也不会把失败原文等内部诊断字段返回前端。

该接口复用 `runtime.config.list` 权限并供前端五秒轮询，不写管理员操作审计和普通访问日志。控制表状态会一次查询，数据库错误不会降级成“控制表未创建”。

请求示例：

```http
GET /api/runtime-config/archive-jobs/5/progress
```

路径参数：

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
| --- | --- | --- | --- | --- |
| `id` | uint64 | 是 |  | 归档任务草稿 ID。 |

### 预检草稿

```http
POST /api/runtime-config/validate
```

返回草稿快照 checksum 和校验信息。预检不改变 active release，也不刷新运行态缓存。

预检执行完成均返回 HTTP 200。草稿不合法时 `valid=false`，`messages` 返回需要修正的配置项；只有读取草稿或生成快照发生服务端异常时才返回错误业务码。

通过示例：

```json
{
  "valid": true,
  "messages": ["归档任务 1 条", "周期任务 4 条"],
  "checksum": "b1dbf79448b31e09700ba3765613936264a2c23254b1270b83a9c3e6c6c2342f"
}
```

未通过示例：

```json
{
  "valid": false,
  "messages": [
    "归档任务 1 条",
    "周期任务 4 条",
    "归档任务 table_name 不能为空 name=archive-admin-log-hourly"
  ],
  "checksum": ""
}
```

### 发布草稿

```http
POST /api/runtime-config/publish
```

请求体：

```json
{
  "remark": "发布说明",
  "twoStepKey": "mfa-ticket-key",
  "twoStepValue": "mfa-ticket-value"
}
```

发布会读取草稿表，生成不可变快照，更新 `runtime_config_state`，并刷新 table-cache 精确 key。数据库事务先对唯一的 `runtime_config_state` 行加排他锁，再读取草稿、写入 release 并切换 active 版本；并发保存或删除必须等待发布事务提交，因此已发布快照与锁获取时刻的草稿一致，后续编辑只进入下一次发布。

响应示例：

```json
{
  "releaseId": 13,
  "versionNo": 13,
  "checksum": "b1dbf79448b31e09700ba3765613936264a2c23254b1270b83a9c3e6c6c2342f",
  "applied": true,
  "restartRequired": false,
  "restartReason": ""
}
```

| 字段 | 说明 |
| --- | --- |
| `applied` | 当前实例是否已经完成缓存刷新和运行态应用。数据库版本提交成功、后续应用失败时返回 `false`，避免客户端把已提交版本当成整次失败重复发布。 |
| `restartRequired` | 当前热加载完成后是否仍需重启才能完全生效。 |
| `restartReason` | 需要重启时的原因。 |

`applied=false` 表示版本已经写入数据库，不能再次提交同一发布动作。`runtime_config.source=database` 时 watcher 会按轮询周期继续应用 active release，应关注热加载状态和失败告警；`file` 模式不启动 DB watcher，数据库发布不会自动应用到当前进程。

### 发布历史与快照

```http
GET /api/runtime-config/releases?page=1&pageSize=20
GET /api/runtime-config/releases/:releaseId
```

详情返回发布快照 JSON 和 YAML。快照只包含：

```yaml
archive_jobs:
  - ...
task_periodic:
  - ...
```

### 回滚发布

```http
POST /api/runtime-config/rollback
```

请求体：

```json
{
  "releaseId": 12,
  "remark": "回滚说明",
  "twoStepKey": "mfa-ticket-key",
  "twoStepValue": "mfa-ticket-value"
}
```

回滚不会复写历史 release，而是基于目标快照创建一个新版本。目标快照覆盖草稿、新增 release 和切换 active 版本在同一个数据库事务中完成；任一步失败时整体回滚，并发草稿编辑等待该事务结束，不会出现草稿已回滚但 active 版本未切换的中间状态。

## 热加载与缓存

- 实例只按 `runtime_config.poll_interval_seconds` 读取 `runtime_config:state`。
- 版本和 checksum 未变化时不读取 release 快照。
- 版本变化时读取 `runtime_config:release:{releaseID}`，缓存 miss 才回源 `runtime_config_release` 单行。
- 保存草稿不刷新运行态缓存；发布和回滚才刷新。
- table-cache 或 Redis 短暂异常时保留当前运行配置并记录日志。
