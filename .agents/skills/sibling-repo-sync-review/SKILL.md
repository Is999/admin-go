# 兄弟仓库同步复核

## 执行流程

1. 用 `realpath` 或 Git 根目录确认每个目标仓库，不凭目录名称猜测。
2. 分别读取生效的 `AGENTS.md`、项目文档、分支、Git 状态和同名文件布局。
3. 传播前并排比较对应文件，区分共享契约、可复用模式和必须保留的项目差异。
4. 保留各仓库自己的服务名、路由、配置键、包名、文档入口、部署方式和验证命令；移除来源仓库措辞和本机绝对路径。
5. 共享 cache/API key、业务码或安全契约默认保持兼容，除非用户明确要求拆分。
6. 同步项目自有 YAML 时，每个目标仓库分别按自己的 config struct/tag、默认值、校验器和 reload 应用器复核固定字段注释；共享字段可以保持相同表述，消费方、默认值或重启边界不同的字段不得机械复制。动态 map 和第三方 schema 分别记录共享说明或排除依据。
7. 同步 DDL/DML 治理时，每个目标仓库都只维护完整初始化基线；不得复制或提交任一仓库 `data/sql-changes` 下的本地 DBA/运维 SQL。
8. 每个仓库独立修改、验证和暂存；一个仓库通过不能证明另一个通过。

## 验证

- 用 `rg` 和 `diff` 检查来源项目名、本机路径、占位符和跨项目描述残留。
- 每个目标仓库分别按对齐记录触发验证：Go 文件运行归属包与直接调用包测试，共享契约/配置/Model/注册清单变化再运行 `go test ./...`；前端 wrapper/type 变化运行 typecheck，可见页面或路由变化补浏览器冒烟；Skill 运行 frontmatter 校验及其脚本测试；纯文档运行本地链接、导航、路径和命令检查。
- 每个仓库运行 `git diff --check`、`git diff --cached --check`（存在 staged 文件时）和 `git status --short`。

## 对齐记录

这份记录用于说明“一项内容为什么传播、传播到哪些仓库、哪些差异必须保留”，不是只适用于固定仓库名称或固定仓库数量的表单。每项共享契约或传播决策分别记录：

```text
同步项与类型:
目标仓库及各自职责:
各仓库源码依据:
必须共享的行为或契约:
各仓库修改文件与动作:
要求字节一致的文件及原因:
必须保留的差异及原因:
每个仓库的验证命令与结果:
未传播内容及原因:
```

按内容类型决定传播边界：

| 内容类型 | 对齐要求 |
| --- | --- |
| API、业务码、Redis Key、数据形状或安全语义等共享契约 | 先确认共同调用方和兼容窗口，再逐仓库同步；不能让一个仓库单方面改变共享语义 |
| 代码、文档或配置的可复用模式 | 传播规则和结构，随后按各仓库真实入口、命名、默认值和验证命令改写 |
| 服务名、路由入口、包名、配置键、权限模型、部署方式和运维职责 | 以目标仓库源码为准保留差异，不为追求文本相同而机械复制 |
| `data/sql-changes`、本地配置、日志、生成物或其它机器本地资产 | 不跨仓库复制、不提交；记录忽略或排除证据 |

只有确属同一 Skill、共享规则或共同契约，且消费方和项目边界完全相同时，才要求文件字节一致。目标仓库数量、名称和角色从本次任务与 Git 根目录动态确定；禁止把示例仓库名写成通用流程的固定字段。无法解释的差异和机械复制出的相同内容都视为待处理问题。

## 交付证据

按对齐记录说明目标仓库、同步文件、字节一致项、保留差异、未传播内容、每个仓库最后一次修改后的验证与暂存状态。禁止只写“已同步到兄弟仓库”。
