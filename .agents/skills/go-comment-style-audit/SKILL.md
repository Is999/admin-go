# Go 注释与可维护性审计

## 执行流程

1. 读取生效的 `AGENTS.md`、AI 开发文档和 `references/project-map.md`。
2. 先查看改动文件、附近调用链和契约语义，再判断注释是否必要和准确。
3. 默认审计改动路径；用户要求全仓或改动触及共享契约时，再扩大到仓库级扫描。
4. 检查新增或重构的变量、常量、方法、结构体、字段、map 字段、路由、GORM Model、接口和关键逻辑，以及新增或修改的项目自有 YAML 固定配置字段是否具有有效中文注释。
5. 注释优先解释业务意图、数据形状、单位、来源、边界、默认行为、性能保护或降级策略；删除重复代码和空泛套话的注释。
6. 同时检查过度封装、隐式魔法、重复抽象和手写高风险基础能力等可维护性问题。
7. 修复后重跑 AST 审计；注释伴随逻辑改动时运行该文件所属包及直接调用包测试，只改注释时至少运行编译或仓库规定的文档/格式检查，最后运行 diff 检查。

## 逐项审计标准

### 声明与契约

- 变量和常量：说明领域含义、单位、取值范围、默认/零值或为什么必须跨语句保留；`ctx`、`err`、`tx` 等约定俗成的短作用域变量按项目规范处理。
- 结构体和字段：说明对象职责、字段来源、空值、时间/金额单位、排序、去重、敏感性以及 map 的 key/value 语义；GORM Model 还要核对表名、主键、索引、NULL、默认值、软删除和时间字段。
- 方法和接口：说明业务动作、前置条件、返回/副作用、幂等或并发边界；接口方法只写能力契约，不重复实现步骤。
- 路由和注册项：说明访问级别、权限/安全策略、审计动作、输入输出和注册目的；仅写“注册路由/组件”不合格。
- 关键逻辑：对事务、锁、状态迁移、重试、超时、降级、批处理、数据修复和不可逆操作说明为什么存在及保护什么边界。
- YAML 固定配置字段：字段正上方必须有同缩进中文注释，说明消费组件和用途；config struct/tag、默认值、normalize/getter、校验器、消费方或 reload 应用器定义了枚举/范围/单位、缺省/空值/零值、reload/restart、敏感信息或跨字段约束时，注释必须覆盖这些真实行为。父节点概述不能替代子字段。
- YAML 动态数据与排除项：动态 map 或重复列表项只有在父字段已说明 key/value、空值、唯一性、顺序和合并规则时才可共享说明；第三方 schema、纯数据清单或生成文件必须记录具体路径、schema 所有者、文件职责和项目代码不读取其字段的证据。

### 有效注释判定

- 有效注释至少增加一项代码本身无法可靠表达的信息：业务原因、数据来源、单位、空值、上限、顺序、并发、失败策略、兼容窗口或安全风险。
- `处理数据`、`执行逻辑`、`优化性能`、`异常兜底`、逐字翻译函数名或逐行复述语句均判定为无效；必须改成可验证业务说明或通过命名/结构删除注释需求。
- 注释与实现、字段类型、默认值或调用链不一致时，优先确认当前代码和权威契约，再修正文档或实现；禁止为了让审计通过保留错误注释。
- 长注释如果只是在解释绕行代码，应先简化命名、分支和抽象；协议、算法、故障模型或运维边界确实复杂时保留结构化说明，不能强行压成一句话。

### 可维护性判定

- 每个新增接口、wrapper、helper、状态和分支必须能指出当前调用方、稳定复用边界或真实故障窗口；只转发参数且无独立职责的包装、重复抽象和孤立脚手架必须报告。
- 主流程必须能直接看到关键校验、状态变化和最终副作用；反射、全局注册、隐式默认值或魔法字符串造成行为不可发现时，要求收口入口并补静态测试。
- 发现手写加密、认证、并发原语、协议解析或迁移框架等高风险基础能力时，检查现有成熟依赖、测试向量和维护责任，不能只标记“实现复杂”。

## 审计脚本

```bash
go run <skill-dir>/scripts/go_comment_audit.go <repo-or-dir>
python3 <skill-dir>/scripts/yaml_comment_audit.py \
  --dynamic-parent redis.addr_map \
  <project-owned-config.yaml> [<project-owned-config.yaml> ...]
```

Go 脚本扫描私有 helper、结构体字段、const/var 声明和匿名局部结构体字段。YAML 脚本检查 block-style mapping 字段是否有紧邻、同缩进且包含中文的上方注释；只有父字段已定义 key/value、空值、唯一性、顺序和合并语义的动态 map，才可用可重复的 `--dynamic-parent <dot.path>` 排除其直接数据 key。文件不是项目应用配置、属于第三方 schema 或生成资产时，不把目录整体传给脚本，改为逐文件记录排除依据。

两个脚本只检查结构线索，不能判断注释内容是否与 config struct/tag、默认值、normalize/getter、校验器、消费方和 reload/restart 一致。变量、常量、接口方法、路由、GORM Model、关键逻辑与 YAML 字段即使未被报告，仍需按项目规范人工复核；YAML 还必须执行解析与配置样例加载测试。

脚本变更后执行：

```bash
go test <skill-dir>/scripts/go_comment_audit.go <skill-dir>/scripts/go_comment_audit_test.go
python3 -m unittest discover -s <skill-dir>/scripts -p 'test_*_audit.py'
```

## 交付证据

按“文件/符号或 YAML 字段、问题类型、缺失语义、源码依据、修复方式、验证”记录审计结果；同时说明脚本命中与漏扫范围、YAML 纳入/排除文件、人工复核对象、最后一次修改后的测试，以及仍需确认的问题。禁止只交付“已补注释、代码更清晰”或“YAML 均有说明”的概括结论。
