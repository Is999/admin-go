# 配置字段说明

## 文档目标

本文档用于说明 `admin` 的主要配置项用途，方便开发、测试、运维在本地部署、联调和生产发布时快速理解配置字段含义。

推荐配合以下文件一起阅读：

- `etc/config.yaml`
- `etc/config.sample.yaml`

## YAML 样例维护约束

- 本文档解释跨字段关系和运行边界，不能替代 YAML 行级注释。项目自有 YAML 的每个固定配置字段必须在字段正上方保留同缩进中文注释；父 mapping 或章节注释不能覆盖子字段。
- 字段注释至少写明消费组件和用途。源码定义了枚举/范围/单位、缺省/空值/零值、normalize/getter、热加载/重启、敏感信息或跨字段约束时，必须把对应行为写入该字段注释，不能用“默认即可”“按需配置”代替。
- 动态 map 或重复列表项由父字段说明 key/value、空值、唯一性、顺序和合并规则；固定 item 结构中的字段仍逐项注释。完整适用范围、排除条件和验收证据见 [AI 开发规范](AI开发规范.md#yaml-配置字段行级注释)。

## 顶层配置

### `Name`

- 服务名称。
- 用于日志、链路追踪、监控平台和服务实例标识。

### `Host`

- HTTP 服务监听地址。
- 本地开发通常使用 `0.0.0.0` 或 `127.0.0.1`。

### `Port`

- HTTP 服务监听端口。
- 用于 API、文档站和健康检查访问。

### `internal_server`

- 独立承载 `/internal/` 路由；公网 `Host/Port` 监听器不注册内网路由。
- `host` 必须是明确 IP。生产仅允许回环或私网地址，不能使用 `0.0.0.0`、`::`，且 `port` 不能与公网端口相同。
- 生产跨主机监听必须同时配置 `cert_file`、`key_file`、`client_ca_file`，服务端强制校验客户端证书；仅回环监听允许使用 HTTP。
- 属于启动期监听配置，热加载变更只标记需重启。

### `ops`

- `token` 是 Admin 内网接口令牌和 HMAC 密钥，最少 16 字符；生产不能使用模板占位值。
- `allowed_ips` 可在回环和私网边界内进一步收窄来源，不能配置公网或跨出私网范围的 CIDR。
- 请求还必须携带时间戳、16 字节随机 nonce、请求体摘要和 HMAC；nonce 由 Redis `SET NX` 防重放，Redis 不可用时失败关闭。

### `api_service`

- Admin 调用 API 独立内网监听器的客户端配置；`internal_base_url` 必须指向 API `internal_server`，`ops_token` 与 API `ops.config_reload_token` 一致。
- 本机回环允许 HTTP；生产跨主机必须使用 HTTPS，并同时配置 `ca_file`、`cert_file`、`key_file`，`server_name` 仅在证书名称与 URL 主机名不一致时填写。
- Admin 每次调用自动生成 nonce，并把 method、完整 URI、时间戳、nonce 和请求体摘要纳入 HMAC。

### `app_id`

- 站点或应用 ID，例如 `203`。
- 必填，用于区分不同站点配置、Redis 命名空间、业务数据和下游消息主题。

### `app_key`

- MFA 与用户邮箱、手机号等持久敏感数据的加密和查询哈希根密钥。
- 数据写入后不能直接轮换；变更必须先设计密钥版本、历史数据回填和回滚方案。
- 属于启动期数据契约，热加载只标记需重启并保留当前进程旧值。

### `trusted_proxies`

- 可信反向代理 IP/CIDR 列表，仅命中列表的远端来源可以提供 `X-Forwarded-For` 或 `X-Real-IP`。
- 空列表保持只信任本机回环代理的安全默认值；生产应按实际 LB/Ingress 地址或网段精确配置，禁止使用全网段。
- 该字段影响登录频控、IP 白名单、审计和链路日志，配置非法时启动失败；热加载变更需重启进程。

### `ip_region`

- 使用本地 `ip2region` XDB 文件解析登录与审计日志中的公网 IP；不会向外部 IP 服务发送请求。
- `enabled=true` 时至少提供 `ipv4_xdb_path` 或 `ipv6_xdb_path` 的绝对路径；相对路径、文件不存在、损坏或版本不兼容都会使启动失败，防止功能静默失效。
- 私网地址显示“内网”、回环地址显示“本机”；公网查询只保留国家、省、市，不保存 ISP 与 ISO 编码。
- 支持 ip2region 内置的 `国家|省|市|ISP|ISO` 五字段，以及在其尾部追加字段的 XDB；前 3 个字段含义或顺序发生变化的自定义库不兼容。
- 启用的 IPv4/IPv6 XDB 会在启动期完整读入只读内存，查询不保留文件句柄且不执行磁盘 I/O；两份文件合计硬上限为 128 MiB，部署需按实际总大小为每个实例预留内存。
- 数据文件不纳入仓库。推荐文件、完整下载命令、SHA-256 校验和回滚步骤见[部署发布指南](../运维/部署发布指南.md#可选本地-ip-归属地数据)。
- 此能力属于启动期资源；更新 XDB 文件或变更任一路径后必须滚动重启，配置热加载不会替换正在使用的查询器。

### `snowflake.redis`

- 生产多实例默认使用 Redis 租约自动分配雪花 node_id，范围 `0-1023`。
- 同一套 `admin/api` 部署必须使用同一 `snowflake.redis.scope`；业务唯一域由调用方传入的 `NextID(namespace)` 决定，例如用户表统一使用 `user`，充值和提现订单可分别使用独立 namespace。
- `namespaces.<namespace>.node_count` 可限制单业务 namespace 的 node_id 池大小；未配置时使用完整 `0-1023`，当前 `user` 配置为 `10` 表示只竞争 `0-9`。
- `lease_seconds` 是 node_id 租约 TTL，允许 `10-86400` 秒；`renew_interval_seconds` 必须小于 TTL 的一半；某个业务 namespace 的租约丢失后，当前进程只会停止该业务继续发号。
- `snowflake.worker_id` 仅用于手工强管控场景；启用 `snowflake.redis.enabled=true` 时不能同时配置 `worker_id`。
- 雪花配置属于启动期配置，热加载变更只会标记为需重启，不会在线切换当前进程的 ID 生成器。

### `snowflake.segment`

- 高吞吐业务可在 `snowflake.segment.namespaces` 按业务 namespace 启用 Redis Segment 本地号段；未配置的业务仍走雪花。
- Segment 每次只向 Redis `INCRBY` 申请一段本地缓存，不做 per-ID Redis 队列；进程崩溃可能产生未使用号段空洞，但不会产生重复 ID。
- Segment 不保留雪花时间位和 worker 位语义；`step` 和 `prefetch_threshold` 必须按业务峰值压测设置，避免过小造成 Redis 频繁申请，过大造成故障时空洞过多。

### `user.route_shard_count`

- 当前用户物理表数量，仅接受 `1/2/4/.../1024`，默认 `1`。
- Admin/API 必须使用相同值，根据稳定的 `user_shard_no` 在应用内定位物理表；Proxy 分支固定为 `1` 并由代理管理物理拓扑。
- 后台用户列表和导出固定走登录身份目录取有界批次，再按物理表分组并使用 `shard_no + id` 查询；深分页、状态筛选和复杂组合查询需接入搜索或额外后台索引。
- 该字段属于启动路由，热加载只标记需要重启；目标表与数据未完成迁移和校验前禁止修改。

### `user.export_split_rows`

- 用户列表异步导出单个 Excel 文件最大行数，默认 `500000`。
- 超过阈值时同一个导出任务会按编号生成多个文件，文件名包含 `part_0001/part_0002` 等顺序号。
- 属于运行期导出策略配置，热加载后新触发的导出任务直接使用最新阈值。

### `Mode`

- 运行环境标识。
- 支持 `dev`、`test`、`rt`、`pre`、`pro`。

### `run_mode`

- 进程启动模式位掩码。
- 支持：
  - `1`：仅 API
  - `2`：仅 Worker
  - `4`：仅 Scheduler
  - `3/5/6/7`：组合模式
- 当启动命令显式传入 `-mode` 时，以命令行为准。
- 当启动命令未传 `-mode` 时，进程会回退到配置文件中的 `run_mode`。
- 如果 `-mode` 和 `run_mode` 都未设置，最终默认回退为 `7`。
- 除 `0` 表示走配置或默认值外，非法模式会启动失败，不会被按位裁剪成其它模式。

### `jwt_secret`

- JWT 签名密钥。
- 用于接口鉴权相关逻辑。
- 生产环境必须替换为强随机字符串。
- `jwt_secret` 与 `jwt_expires_in` 共同决定登录态契约，热加载变更只标记需重启并保留当前进程旧值。

### `jwt_expires_in`

- JWT 与 Redis 登录态的有效期，单位秒，默认 86400。
- 登录态不做滑动续期，避免会话超过 JWT 固定过期时间。

## 后台接口安全配置 `security.secret_key`

`security.secret_key` 只服务当前 `app_id`。请求 AppID 不匹配时，秘钥配置从主库和缓存回源。

- `sign_status`：签名验签开关，`1` 启用，`0` 停用；与 `crypto_status` 独立。
- `crypto_status`：加密解密开关，`1` 启用，`0` 停用；与 `sign_status` 独立。
- `key_version`：默认秘钥版本，对应 `X-Key-Version`。
- `aes_key_ref` / `aes_iv_ref`：AES KEY 与 IV 文件路径。
- `rsa_public_key_user_ref`：用户 RSA 公钥文件路径。
- `rsa_private_key_server_ref`：服务端 RSA 私钥文件路径。
- `rsa_public_key_server(_ref)`：服务端 RSA 公钥文本或文件路径；为空时由服务端私钥派生。

## 文件存储配置 `file_storage`

- `type`：存储实现，只允许小写 `local` 或 `s3`；为空按 `local` 处理。
- `upload_mode`：上传模式，只允许小写 `server` 或 `direct`；`direct` 仅允许配合已启用的 S3。
- `local.root_dir`：本地文件根目录；为空回退系统临时目录。容器部署时应挂载持久卷。
- `local.domain`：本地文件访问域名；只填写受信任的实际访问入口。
- `s3.enabled`：是否启用 S3。`type=s3` 时必须为 `true`。
- `s3.bucket` / `s3.region`：S3 必填定位参数。
- `s3.access_key` / `s3.secret_key`：显式凭证，必须同时配置或同时留空；留空时使用 AWS 默认凭证链。
- `s3.path_prefix` / `s3.domain` / `s3.endpoint` / `s3.use_path_style`：对象前缀、自定义域名和兼容 S3 服务参数。
- `s3.presign_expire_seconds`：直传预签名有效期，默认 900 秒。
- `virus_scanner.name`：只允许 `noop` 或 `clamav`；为空或 `noop` 时不执行病毒扫描，所有环境均可使用。
- `virus_scanner.command` / `virus_scanner.config_file`：仅 `clamav` 生效，用于配置 `clamdscan` 命令和 `clamd.conf` 路径；命令为空时从 `PATH` 查找，配置文件为空时使用客户端默认值。
- `virus_scanner.timeout_seconds`：单文件扫描总超时，默认 120 秒，最大 600 秒。
- `upload_session.root_dir` / `upload_session.ttl_seconds`：分片上传临时目录和会话有效期，默认 24 小时；新建上传时会按小时小批量清理已过期且没有有效会话的 `.part` 文件，持久化对象按该 TTL 投递精确清理任务。

上传对象清理复用维护队列，因此文件上传要求 `task.enabled=true`；任务不可用时初始化上传会明确失败，不会产生无人回收的持久化对象。

服务启动时会创建对象存储。配置 `noop` 时不依赖外部扫描软件；配置 `clamav` 时会用空流检查 daemon，扫描命令或 daemon 不可用会直接启动失败。

整个 `file_storage` 属于启动期配置。热加载检测到任一子字段变化时只会标记 `restartRequired` 并保留当前进程的完整旧值，不会在线切换对象存储、病毒扫描器或上传会话；配置变更后必须滚动重启实例。

## 日志配置 `log`

### `log.level`

- 日志级别。
- 常用值：`debug`、`info`、`warn`、`error`。

### `log.mode`

- 日志输出方式。
- `console` 表示输出到控制台，`file` 表示输出到文件。

### `log.path`

- 日志文件目录。
- 当 `mode=file` 时生效。

### `log.encoding`

- 日志编码格式。
- 常用值：`plain`、`json`。

### `log.rotation`

- 日志切割策略。
- 常用值：`size`、`time`。

### `log.max_size`

- 单个日志文件最大大小，单位 MB。

### `log.max_backups`

- 日志归档保留数量。

### `log.keep_days`

- 日志保留天数。

### `log.compress`

- 是否压缩归档日志。

## MySQL 配置 `mysql`

`mysql` 是当前项目唯一必填的 MySQL 启动入口。默认所有业务表都使用该主库连接。

字段结构：

- `write_data_source`：主库 DSN
- `read_data_sources`：从库 DSN 列表
- `max_open_conns`：最大打开连接数
- `max_idle_conns`：最大空闲连接数
- `conn_max_lifetime`：连接最大存活时间，单位秒
- `debug`：是否输出 SQL 调试日志

启动时必须提供 `mysql.write_data_source`。如果需要读写分离，可填写 `mysql.read_data_sources`；为空时所有读写都走主库连接池。

## 命名扩展库配置 `site_mysql`

`site_mysql` 是可选扩展配置，不参与默认部署。只有确实需要把某类表拆到独立 MySQL 时，才补命名节点：

```yaml
site_mysql:
  archive:
    write_data_source: "user:password@tcp(mysql:3306)/admin_archive?charset=utf8mb4&parseTime=true&loc=Local"
    read_data_sources: []
    max_open_conns: 20
    max_idle_conns: 10
    conn_max_lifetime: 300
    debug: false
```

注意：

- 不配置 `site_mysql` 时只使用 `mysql`。
- 扩展库名称只做前后空白整理；命名应短而明确，便于运维识别。

## Redis 配置 `redis`

这组配置用于主 Redis 连接。

### `redis.type`

- Redis 连接模式。
- `single` 表示按单节点 Redis 客户端建连。
- `cluster` 表示按 Redis Cluster 客户端建连。
- 建议显式配置，避免只靠地址数量推断连接模式。

### `redis.addrs`

- Redis 节点地址列表。
- 单机 Redis 填 1 个地址。
- Redis Cluster 建议填写多个可访问节点，客户端会按集群拓扑路由。

### `redis.addr_map`

- 仅用于 `redis.type=cluster`；单机模式配置非空映射会导致启动校验失败。
- key 是唯一的集群节点公告主机名，value 是当前进程可达的主机名或 IP；key/value 为空、含首尾空白或同一 key 重复配置均不符合配置契约。
- 映射条目顺序不影响结果，空表表示不改写；本字段随 Redis 客户端在进程启动时读取，不与外置运行期文件合并，修改后必须重启。
- 启动预探测和正式 Cluster 客户端使用同一映射，避免预探测通过的地址与拓扑发现后的连接地址不一致。

### `redis.password`

- Redis 认证密码。
- 无密码可留空。

### `redis.db`

- Redis DB 编号。
- Cluster 模式通常固定为 `0`。

### `redis.pool_size`

- Redis 连接池大小。

### `redis.tls`

- 是否启用 TLS 连接 Redis。
- 对云 Redis、托管 Redis、代理层要求 TLS 的场景需要开启。

### `redis.tls_insecure_skip_verify`

- 是否跳过 TLS 证书校验。
- 仅测试环境、代理转发或证书不完整的特殊场景建议开启。
- 生产环境通常建议关闭。

## Kafka 配置 `kafka`

这组配置承载 Kafka 公共连接参数和按业务划分的 Topic。`collector.kafka` 未单独配置 broker、批次和写超时时会继承这里。

### `kafka.enabled`

- 是否启用公共 Kafka 生产者。

### `kafka.brokers`

- Kafka broker 地址列表。
- Collector Kafka 未配置 `brokers` 时会继承该值。

### `kafka.batch_size`

- 单批次最大发送消息数。
- Collector Kafka 未配置 `batch_size` 时会继承该值。

### `kafka.write_timeout`

- Kafka 写超时时间，单位秒。
- Collector Kafka 未配置 `write_timeout` 时会继承该值。

### `kafka.topics.user_tag`

- 可供自定义用户标签事件 hook 使用的 Topic。
- 默认用户标签骨架不直接写入 Kafka。

## 通用收集器配置 `collector`

这组配置用于把高频结构化事件写入 Kafka，再由 Worker 批量投送给 Processor。调用方只投递数据，不投递 SQL；处理失败后的事件进入失败账本、死信和人工重试记录。
管理员审计日志 `admin_log` 也走该链路：API 投递 Collector，Worker 按批次写入数据库，降低接口高峰期直接写库压力。

### `collector.enabled`

- 是否启用通用收集器。
- API-only 模式只保留 `Enqueue` 能力；后台 Kafka 消费和失败账本重试 worker 只在 Worker 模式启动。
- 管理员审计日志已统一走 Collector，生产模式必须保持启用；关闭时启动校验会直接拒绝运行。

### `collector.kafka.brokers`

- Kafka broker 地址列表。
- 为空时继承 `kafka.brokers`。

### `collector.kafka.write_batch_size`

- Kafka producer 写入批次大小。
- 小于等于 0 时继承 `kafka.batch_size`。
- 该字段只控制 Kafka 写入 flush，不表示某个业务 Processor 的批量触发规则。

### `collector.kafka.write_batch_wait_milliseconds`

- Kafka producer 写入批次等待时间，单位毫秒。
- 业务 Processor 的本地批量触发规则请配置 `collector.default_task` 或 `collector.tasks.<bizType>`。

### `collector.kafka.write_timeout`

- Kafka 写超时时间，单位秒。
- 小于等于 0 时继承 `kafka.write_timeout`。

### `collector.kafka.read_timeout`

- Kafka 读超时时间，单位秒。

### `collector.default_task.topic`

- 未单独配置 `collector.tasks.<bizType>.topic` 时使用的默认 Kafka Topic。
- 新业务建议显式配置自己的 `collector.tasks.<bizType>.topic`，便于隔离 payload、权限和容量。

### `collector.default_task.group_id`

- 未单独配置 `collector.tasks.<bizType>.group_id` 时使用的默认 Kafka 消费组。
- 同一个 Topic 在同一 Collector 实例中只能使用一个 group_id，避免重复消费。

### `collector.default_task.batch_size`

- 未单独配置 `collector.tasks.<bizType>` 时，同一 `BizType` 在同一 partition lane 内的最大聚合条数。
- 小于等于 0 时使用默认值 `500`。

### `collector.default_task.batch_wait_milliseconds`

- 未单独配置 `collector.tasks.<bizType>` 时，同一 `BizType` 未满批的最大等待时间，单位毫秒。
- 小于等于 0 时使用默认值 `20`。

### `collector.default_task.processor_timeout_seconds`

- Processor 单批执行超时，默认 `300` 秒，最大 `3600` 秒。
- 超时会取消当前上下文；业务 Processor 必须把该上下文传给数据库、HTTP 和其它下游调用。

### `collector.idempotency.enabled`

- Collector Redis 单任务 EventID 去重默认开关。
- 默认 `false`，避免所有任务都强制访问 Redis；需要跨 Kafka 重投去重的任务通过 `collector.tasks.<bizType>.idempotency_enabled=true` 单独开启。

### `collector.idempotency.ttl_seconds`

- Redis 单任务 EventID 幂等终态保留时间，单位秒。
- 默认 `3600`，用于让成功事件和已进入失败账本的事件在重启、重平衡或 Kafka 重投后继续被跳过。
- 该值应按 Kafka 重投窗口和 Redis 容量压测调整；高吞吐 Collector 不建议配置过长，避免高基数 key 长时间占用 Redis。
- 仅对已启用 `idempotency_enabled` 的任务生效；该配置只控制 Collector 自身去重缓存，Redis 不参与正常事件投递或消息中转。

### `collector.idempotency.processing_ttl_seconds`

- Redis 单任务 EventID 处理中占用租约时间，单位秒。
- 默认 `600`，Worker 在 Processor 前用随机 token 原子占用 `BizType + EventID`，处理期间自动续租。
- 续租和终态写入均校验 token；旧领取者不能覆盖新领取者。进程退出后租约到期，Kafka 重投可重新处理。
- 必须在 `3-86400` 秒内且小于等于 `collector.idempotency.ttl_seconds`。

### `collector.idempotency.pipeline_batch_size`

- 单次 Redis Pipeline 最大命令数，默认 `200`，最大 `1000`。
- Collector 不使用多 key Lua、MGET/MSET 等跨 slot 操作；单节点和 Redis Cluster 都按单 key 命令执行，Pipeline 只用于降低网络往返。
- 高吞吐业务建议结合 Redis 延迟压测调小该值，避免单次 Pipeline 过大导致 Redis 执行抖动。

### `collector.failure_retry.runner_batch_size`

- 失败账本 worker 单轮领取失败事件上限，也是投送给 Processor 的批量上限。
- 该 worker 只扫描失败、死信和人工重试记录，不扫描正常成功事件。
- 默认 `500`，最大 `5000`。

### `collector.failure_retry.runner_interval_seconds`

- 失败账本 worker 活跃轮询间隔，单位秒；领取到任务后恢复该间隔，空闲时逐步退避，默认最长 `5` 秒。

### `collector.failure_retry.running_lease_seconds`

- 重试中事件租约时间，单位秒。
- 默认 `600`，允许范围 `3-3600`；处理期间按 `claim_token` 自动续租。
- 过期租约按当前租约的十分之一检查，并限制在 `30-60` 秒，避免每次到期任务扫描都重复查询运行态记录。
- 完成、失败、回收都必须匹配当前 token；失权会取消 Processor，旧 Worker 不能回写新领取者状态。

### `collector.failure_retry.max_retry_times`

- 最大失败重试次数。
- 达到该次数后事件进入死信，等待人工重试或排障。

### `collector.tasks.<bizType>.topic`

- 指定业务类型使用的 Kafka Topic，`<bizType>` 必须等于投递事件里的 `Event.BizType`。
- 未配置时继承 `collector.default_task.topic`。
- 不同 payload、不同容量或不同权限边界的任务应使用不同 Topic。

### `collector.tasks.<bizType>.group_id`

- 指定业务类型消费该 Topic 的 Kafka 消费组。
- 未配置时继承 `collector.default_task.group_id`。
- 同一个 Topic 配置多个任务时 group_id 必须一致，否则启动校验失败。

### `collector.tasks.<bizType>.batch_size`

- 指定业务类型的最大聚合条数，`<bizType>` 必须等于投递事件里的 `Event.BizType`。
- 示例：`collector.tasks.admin_log.audit.batch_size=200` 表示审计日志同任务累计到 200 条立即触发 `Processor.ProcessBatch`。
- 未来其它业务可以独立配置，例如 `collector.tasks.user_stat.batch_size=500`，不会影响 `admin_log.audit`。

### `collector.tasks.<bizType>.batch_wait_milliseconds`

- 指定业务类型未满批时的最大等待时间，单位毫秒。
- 最大允许 `60000`，避免单个 partition lane 因误配置长时间阻塞。
- 示例：`collector.tasks.admin_log.audit.batch_wait_milliseconds=3000` 表示审计日志未满 200 条时最多等 3 秒。

### `collector.tasks.<bizType>.processor_timeout_seconds`

- 覆盖默认 Processor 单批执行超时；未配置时继承 `collector.default_task.processor_timeout_seconds`。
- 最大允许 `3600` 秒。到期后框架会取消 context 并同步等待 Processor 返回；Processor 必须遵守 context 才能及时退出。

### `collector.tasks.<bizType>.idempotency_enabled`

- 指定业务类型是否启用 Redis 单任务 EventID 去重。
- 未配置时继承 `collector.default_task.idempotency_enabled`；仍未配置时继承 `collector.idempotency.enabled`。
- 调用方已经保证幂等、或业务允许重复处理时建议关闭，避免增加 Redis 压力和批处理耗时。

Collector 的 Redis token 只保护运行期领取权，不能替代业务持久幂等。Processor 在数据库写成功后仍可能遇到 Redis 或 Kafka 确认失败，因此生产写入必须使用唯一业务键或幂等 upsert；内置 `admin_log.audit` 使用 `admin_log.event_id` 唯一索引。

## CDC 配置 `cdc`

消费 Debezium Kafka 事件，仅 worker 模式启动；变更后需重启。

### `cdc.enabled`

- 是否启用 CDC 消费器。
- 当前仓库只有 `admin_log` 本地验证处理器，生产模式会拒绝启用；正式清洗器交付并证明下游幂等前必须保持关闭。

### `cdc.brokers`

- Kafka broker 地址列表。
- 为空时继承 `kafka.brokers`。

### `cdc.group_id`

- Kafka 消费组 ID，用于控制 offset 和多实例分摊。

### `cdc.consumer_name`

- 当前进程消费者名称前缀，用于日志和后续排障。

### `cdc.read_timeout_seconds`

- 单次 Kafka 读取超时时间，单位秒。

### `cdc.retry_backoff_seconds`

- 处理失败后的重试间隔，单位秒。

### `cdc.max_retry_times`

- 单条消息最大失败次数。

### `cdc.dead_letter_topic`

- 死信 Topic；为空时失败消息不提交。

### `cdc.topics`

- Debezium Topic 消费规则列表。
- `topic` 是 Kafka Topic 名称。
- `table` 是表路由键，格式为 `db.table`。

`test_scenarios.admin_log_audit` 仅用于本地验证；生产模式会拒绝启用 Lark 或 Collector 输出。

## 通用归档配置 `archive`

这组配置控制热表到历史表的归档节奏和保留边界。

### `archive.enabled`

- 是否启用通用归档模块。

### `archive.safe_delay_minutes`

- 安全归档延迟，单位分钟。
- 归档上界会同时受 `archive_jobs[].archive_delay_days` 和该安全延迟约束，避免归档仍可能被业务修改的近实时数据。

### `archive.lock_ttl_seconds`

- 归档规划、watermark 推进和历史表清理的短锁 TTL，单位秒。

### `archive.lease_ttl_seconds`

- 单个归档区间被 worker 领取后的租约 TTL，单位秒。
- worker 异常退出后，租约过期的区间会被其它 worker 重新领取。
- 归档 checkpoint、完成和失败终态都校验 `worker_id + attempt_count + 未过期租约`；同一工作流重试复用 worker 标识时，旧领取轮次仍无法覆盖新轮次。

### `archive.max_concurrent_jobs`

- 单次归档工作流内不同归档目标的并发数。
- 配置会被代码硬上限保护，避免多个大表归档同时打满同一套 MySQL I/O。

### `archive.default_batch_size`

- 默认单批搬迁条数。
- 代码会限制到安全上限，避免误配置生成过大的 `IN` 条件和事务。
- 每个归档热表必须由 DBA 确认存在以 `time_column` 为首列的索引，并用目标环境 `EXPLAIN` 核对窗口过滤、`ORDER BY time_column, primary_key` 和批量上限。当前 `admin_log` 初始化资产 `internal/database/assets/admin_log.sql` 定义 `KEY idx_created_at (created_at)`；归档预检接受时间列左前缀索引，因为 InnoDB 二级索引叶子包含主键。其它表不能照搬该结论，必须按实际存储引擎、主键和执行计划判断是否需要复合索引。

### `archive.default_delete_batch_size`

- 默认单批删除条数。
- 删除只按已经复制并校验成功的主键集合执行，避免对热表做无界条件删除。
- 删除期间按租约三分之一间隔续租，每批写入前再校验 `worker_id + attempt_count` fencing；单轮最多连续删除 100 批，剩余数据由后续调度继续处理。

### `archive.batch_delay_milliseconds`

- 每个归档批次提交后的保护性等待时间，单位毫秒。
- 大量历史积压时用于主动让出 MySQL I/O，降低连续 `INSERT ... SELECT` 和 `DELETE` 对主库的冲击；配置过大时会被代码硬上限保护。
- 生产建议初始值为 `200`，表示每个已提交批次后等待 200ms；在当前 `admin_log` 单批归档 `3000`、单批删除 `1000`、2 个 worker
  的配置下，能让 MySQL 有短暂 I/O 和锁释放窗口，同时不会明显拉长小时级归档任务。
- 调优建议：MySQL 压力平稳但历史积压明显时可用 `100~200`；出现写入 RT 升高、锁等待、IOWait 或从库延迟时临时调到 `300~500`
  ；只有低峰大回补且业务压力很高时才临时使用 `800~1000`。不建议长期超过 `1000`，代码硬上限为 `5000ms`。
- 估算执行时间时按“批次数 × 等待时间”计算额外耗时；例如 200 个批次、`200ms` 等待约增加 40 秒，`500ms` 等待约增加 100 秒。

### `archive.default_max_history_tables`

- 每个归档任务默认保留的历史表数量。
- 超出后按最老历史表优先淘汰，单次只处理少量历史表，剩余表留给下一轮低峰任务继续清理。

### `archive_jobs`

- 单表归档策略列表，发布后由运行配置数据表 active release 承载。
- `runtime_config.source=file` 时继续读取 `config_files.runtime`；`database` 时 YAML 中的 `archive_jobs` 仅作为手动导入或草稿为空时的兼容种子，不参与后续合并。
- 归档工作流 `archive.run` 的 `targets` 支持三种写法：
    - `admin_log`：同一轮先归档再删除，适合单周期串行处理。
    - `admin_log#archive`：只规划和搬迁归档窗口，适合每 15 分钟或每小时追水位。
    - `admin_log#delete`：只删除已归档且达到删除边界的热表数据，适合与归档不同频率调度。

### `archive_jobs[].database`

- 热表和历史表所属数据库，默认填写 `main`。
- 如需使用扩展库，填写 `site_mysql.<name>` 中的 `<name>`。
- 归档控制表 `archive_segment`、`archive_watermark` 默认使用主库，除非归档组件显式覆盖。

### `archive_jobs[].time_column_type`

- 归档时间列类型，支持 `time`、`string`、`unix`；为空默认 `time`。
- `time` 由数据库驱动解析为 `time.Time`；`string` 按字符串时间处理；`unix` 按 Unix `int64` 处理。

### `archive_jobs[].time_column_format`

- 字符串时间列格式，仅 `time_column_type=string` 生效，使用 Go layout。
- 为空默认 `2006-01-02 15:04:05`；如列值为 `2026/05/28 13:27:00`，配置 `2006/01/02 15:04:05`。
- 字符串时间列必须使用可按字典序比较时间先后的格式；只有日期粒度的格式不会启用秒级归档/删除窗口。

### `archive_jobs[].time_column_unix_unit`

- Unix 整数时间单位，仅 `time_column_type=unix` 生效。
- 支持 `seconds`、`milliseconds`；为空默认 `seconds`。

### `archive_jobs[].archive_condition`

- 自定义归档过滤条件，留空表示当前时间窗口内全部数据都参与归档。
- 条件会同时作用于首次最小时间探测、归档游标读取和 `INSERT ... SELECT`
  复制事务；复制事务会再次叠加主键集合与时间半开窗口，避免跨窗口写入历史表。只能配置无占位符、无注释、无子查询、无写入动作的
  `WHERE` 谓词片段，例如 `status = 1 AND is_deleted = 0`。
- 调整该条件只影响尚未处理的归档窗口；已完成窗口如果需要重新纳入或排除数据，必须配合人工回退水位/区间或补偿任务。

### `archive_jobs[].delete_condition`

- 自定义热表清理附加条件，留空表示清理条件只继承 `archive_condition` 和时间窗口。
- 实际删除时会按 `archive_condition AND delete_condition`
  生效，并在读取待删主键后、事务删除前再次校验主键集合、当前删除窗口和归档区间，避免归档条件只覆盖部分行时误删未归档数据或跨窗口删除。
- 条件安全规则与 `archive_condition` 相同；如果变更条件导致旧窗口仍有热表残留，需要通过后续删除任务继续清理或执行人工补偿。

### `archive_jobs[].split_unit`

- 历史表物理拆分粒度，支持 `none/year/quarter/month/week/day/custom_days`。
- `none` 表示所有历史数据写入固定历史表；其它值按时间生成不同历史表。
- `split_unit` 控制历史表命名和建表数量，不再强制等同于归档或删除窗口。

### `archive_jobs[].hot_keep_days`

- 热表目标保留天数。
- `delete_delay_days <= 0` 时会默认使用该值，表示数据至少保留这么多天后才允许物理删除。

### `archive_jobs[].archive_delay_days`

- 归档从几天前开始推进。
- 例如 `2` 表示每个周期归档两天前对应时间窗；`<=0` 时默认等于 `hot_keep_days`。
- `archive_watermark.watermark_time` 只表示该排他上界之前、满足归档条件的数据已完整复制到历史表，不表示热表已经删除；热表删除边界由 `delete_delay_days` 和 `delete_window_seconds` 独立控制。

### `archive_jobs[].archive_window_seconds`

- 单个归档窗口秒数。
- `900` 表示按 15 分钟窗口归档，`3600` 表示按 1 小时窗口归档；`<=0` 时按 `split_unit` 规划归档区间。
- 配置窗口后仍会受 `split_unit` 自然边界保护，避免按天、按月历史表出现跨天或跨月数据。
- 首次无水位线时会从最早可归档数据所在窗口开始追水位，避免因月中首条数据而从月初空窗口慢慢推进。

### `archive_jobs[].archive_window_mode`

- 归档窗口推进模式，支持 `auto`、`fixed`，为空默认 `auto`。
- `fixed` 严格按 `archive_max_windows_per_run` 和 `delete_max_windows_per_run` 推进，适合要求每轮固定窗口数的低扰动场景。
- `auto` 先按 `archive_max_windows_per_run` 推进基础窗口；若上一窗口行数和耗时都很轻，会继续追赶到 `archive_auto_max_windows`，用于空窗口或稀疏数据快速追平水位。
- 删除阶段也复用 auto 轻量阈值；旧空窗口或稀疏窗口会继续追赶，遇到重删除窗口或未推进窗口后停止本轮追赶。

### `archive_jobs[].archive_max_windows_per_run`

- 单次运行最多归档窗口数。
- 窗口模式默认 `1`；在 `fixed` 模式中这是严格上限，在 `auto` 模式中这是基础窗口数。

### `archive_jobs[].archive_auto_max_windows`

- `auto` 模式单次最多追赶窗口数。
- 默认 `200`，代码硬上限为 `1000`；该值不会小于归档或删除基础窗口数，删除阶段也受该值限制。

### `archive_jobs[].archive_auto_light_rows`

- `auto` 模式判断轻量窗口的行数阈值。
- 默认 `20000`，代码会按单批安全上限裁剪；窗口归档/删除行数大于该值时，本轮不再继续额外追赶。
- 删除阶段还会受 `delete_batch_size` 限制，避免连续清理重窗口。

### `archive_jobs[].archive_auto_light_ms`

- `auto` 模式判断轻量窗口的耗时阈值，单位毫秒。
- 默认 `3000`，代码硬上限为 `30000`；归档或删除窗口耗时大于该值时，本轮不再继续额外追赶。

### `archive_jobs[].delete_disabled`

- 是否禁用热表删除。
- `true` 表示只归档不删除，适合上线初期观测历史表完整性。

### `archive_jobs[].delete_delay_days`

- 删除从几天前开始推进。
- 默认等于 `hot_keep_days`，可独立设置为大于 `archive_delay_days`，实现“先归档两天前数据，热表保留 32 天后再删”。

### `archive_jobs[].delete_window_seconds`

- 单次删除窗口秒数。
- 删除节点会在已归档区间内按该窗口逐片删除，即使历史表按月分表，也不会一次删除整月热表数据。

### `archive_jobs[].delete_max_windows_per_run`

- 单次运行最多删除窗口数。
- 删除窗口大于归档窗口且未显式配置时，程序会按二者比例补齐默认值，例如 1 小时删除窗口对应 4 个 15 分钟归档窗口。
- `archive_window_mode=auto` 时，该值是删除基础窗口数；旧空窗口或稀疏窗口可继续追赶到 `archive_auto_max_windows`，但超过轻量阈值、`delete_batch_size` 或耗时阈值后会停止本轮追赶。

### `archive_jobs[].history_table_name_rule`

- 历史表命名模板，留空时按 `history_table_prefix + split_unit` 使用内置命名。
- 支持 `{prefix}`、`{table}`、`{yyyy}`、`{yyyymm}`、`{yyyymmdd}`、`{isoweek}`、`{quarter}`、`{range_start}`、`{range_end}` 占位符。
- 渲染结果必须符合 MySQL 标识符规则，只允许字母、数字和下划线，避免动态表名注入。

## 用户标签配置 `user_tag`

这组配置控制用户标签工作流的默认运行参数。

当前业务计算阶段仍是 dry-run 骨架，生产环境会拒绝启用 `workflows.user_tag.enabled`；完成正式计算、结果校验和回滚链路前必须保持关闭。

### `user_tag.enabled`

- 是否启用用户标签模块。
- 启动期注册开关；实例以 `false` 启动时不会注册 `user_tag` handler 和 workflow，热加载改成 `true` 后需要重启实例才能生效。

### `user_tag.event_hook_enabled`

- 是否启用标签得失事件 hook 派发。
- 未注册 hook 时保持关闭；开启后 outbox 中已有事件但无 hook 会进入重试状态。

### `user_tag.default_shard_total`

- 默认工作流任务分片总数。
- 用于全量、增量、定向任务的分片并发计算；与物理分表数量独立，小量数据默认从 1 开始，按吞吐压力再扩。

### `user_tag.default_batch_size`

- 默认单批处理数量。
- 主要用于运行期 UID 和通用阶段游标处理。

### `user_tag.default_worker_count`

- 节点内部 worker 默认值。
- 当前骨架只用于参数校验和后续扩展预留。

### `user_tag.diff_batch_size`

- 标签差异解析批次大小。
- 后续接入 `resolve_changes` 时用于控制单批差异计算规模。

### `user_tag.event_batch_size`

- 事件 outbox 派发批次大小。
- `dispatch_hooks` 和 `user_tag.event_outbox.retry_scan` 使用该值控制单轮派发规模；异常扫描会覆盖所有 outbox 分片，不只处理 0 号分片。

## 任务系统配置 `task`

这组配置用于 Asynq 风格任务队列、工作流节点调度和周期任务投递。

### `task.enabled`

- 是否启用任务系统。

### `task.default_queue`

- 默认投递队列名。

### `task.concurrency`

- Worker 并发数，最大 `256`。

### `task.strict_priority`

- 是否启用严格优先级消费。

### `task.queues.critical`

- 高优先级队列权重，范围 `1~100`；全部监听队列最多 `32` 个。

### `task.queues.default`

- 默认队列权重。

### `task.queues.maintenance`

- 运维、缓存刷新、低优先级后台任务队列权重。

### `task.redis.addrs`

- 任务系统专用 Redis 地址列表。
- 如果不单独配置，可复用全局 `redis`。

### `task.redis.type`

- 任务系统 Redis 连接模式。
- `single` 表示单节点 Redis。
- `cluster` 表示 Redis Cluster。

### `task.redis.addr_map`

- 仅用于 `task.redis.type=cluster`；任务系统未单独配置 Redis 时复用全局 `redis.addr_map`。
- key 是唯一的集群节点公告主机名，value 是 Admin API、Worker 和 Scheduler 进程可达的主机名或 IP；条目顺序无意义，空表表示不改写。
- 本字段属于任务 Redis 客户端启动配置，不由 `runtime_config.source` 合并或热加载；修改后必须重启使用任务 Redis 的全部进程。

### `task.redis.password`

- 任务 Redis 密码。

### `task.redis.db`

- 任务 Redis DB 编号。

### `task.redis.pool_size`

- 任务 Redis 连接池大小。

### `task.redis.tls`

- 是否启用任务 Redis 的 TLS 连接。

### `task.redis.tls_insecure_skip_verify`

- 是否跳过任务 Redis 的 TLS 证书校验。

### `task.default_retry`

- 默认任务重试次数，范围 `0~25`。

### `task.default_timeout_seconds`

- 默认任务超时时间，单位秒，范围 `0~86400`；`0` 表示使用组件默认值。

### `task.default_unique_ttl_seconds`

- 默认任务唯一键 TTL，单位秒，范围 `0~2592000`；`0` 使用内置默认值。

### `task.shutdown_timeout_seconds`

- Worker 优雅退出等待时间，单位秒，最大 `300`。

### `task.task_check_seconds`

- 普通任务轮询间隔，单位秒，最大 `60`。

### `task.delayed_task_check_seconds`

- 延迟任务检查间隔，单位秒，最大 `60`。

### `task.group_grace_period_seconds`

- 任务分组聚合等待窗口，单位秒，最大 `300`，且不能大于最大等待时间。

### `task.group_max_delay_seconds`

- 任务分组聚合最大等待时间，单位秒，最大 `3600`。

### `task.group_max_size`

- 单次聚合最大任务数，最大 `1000`。

### `task.archived_retention_seconds`

- 归档失败任务保留时长，单位秒。
- 用于失败任务排查窗口；过期后清理 archived 索引、任务详情和运行耗时快照。
- 该值是最长时间窗口；Asynq `v0.26.0` 每队列 archived 还受 `10000` 条框架容量上限约束，高失败率时可能更早淘汰，页面会以 Redis 实际存在性决定能否重跑。

### `task.completed_retention_seconds`

- Asynq 成功任务及成功工作流热状态保留时长，单位秒，范围 `600~7200`，未配置默认 `1800`。
- 该窗口只服务近期排障；短期工作流汇总、容量受限的自适应明细和最终失败摘要由历史收集器异步落库。

## 任务历史配置 `task.history`

### `task.history.enabled`

- 是否启用终态历史异步落库，未配置默认启用；关闭后数据库历史接口和数据库版日报不可用。

### `task.history.workflow_retention_days`

- 工作流终态汇总保留天数，未配置默认 `7`，最大 `30`。

### `task.history.task_retention_days`

- 全部实际任务终态摘要保留天数，未配置默认 `1`，最大 `30`；不保存原始业务载荷和结果。工作流入口、节点和分片只保存紧凑汇总及处理计数，完整工作流快照由 `task_workflow_run` 单独保存。

### `task.history.failure_retention_days`

- 最终失败摘要保留天数，未配置默认 `14`，最大 `30`；不保存原始业务载荷和结果。

### `task.history.pending_limit`

- Redis 待落库事件数量硬上限，未配置默认 `2000`，最大 `10000`；同时受代码级 `64 MiB` 总载荷硬上限约束。任一上限达到时丢弃最老事件并暴露 `dropped`、`pendingBytes` 和 `pendingMaxBytes` 指标，禁止无界挤占 Redis。

### `task.history.flush_interval_seconds`

- Worker 收集器批量落库间隔，未配置默认 `5` 秒，最大 `10` 秒；单次租约最多连续写入 `5` 个百条批次，积压较低时提前结束。

### `task.history.cleanup_interval_seconds`

- 短期历史小批量清理间隔，未配置默认 `60` 秒，允许 `30-3600` 秒；每轮仅清理受控主键批次。

### `task.scheduler.enabled`

- 是否启用调度器 leader。

### `task.scheduler.lease_key`

- 调度器 leader 锁 key。

### `task.scheduler.lease_ttl_seconds`

- leader 锁过期时间，单位秒，最大 `300`。

### `task.scheduler.renew_interval_seconds`

- leader 续约间隔，单位秒，必须小于租约时间。

### `task.scheduler.sync_interval_seconds`

- 周期任务配置同步间隔，单位秒，最大 `3600`。

### `task.scheduler.heartbeat_interval_seconds`

- 调度器心跳间隔，单位秒，最大 `300`。

### `task.scheduler.max_queue_backlog`

- 周期任务投递前允许的目标队列积压上限；未配置或等于 `0` 时使用安全默认值 `10000`，硬上限 `100000`，不允许关闭背压。

## 周期任务配置 `task_periodic`

周期任务大列表不再写入主配置 `task.periodic`。默认数据库模式下，通过后台“任务运维 / 运行配置”维护草稿并发布 active release。

单应用最多启用或发布 `1000` 条周期任务，超过上限会在启动或发布校验阶段拒绝，避免调度同步和 Redis 元数据无界增长。

`runtime_config.source=file` 时，仍可从 `config_files.runtime` 指向文件读取顶层 `task_periodic`；`database` 时 YAML 中的 `task_periodic` 仅作为手动导入或草稿为空时的兼容种子。

### `task_periodic[].name`

- 周期任务名称。

### `task_periodic[].enabled`

- 是否启用该周期任务。
- 未配置时默认启用；只有显式配置 `enabled: false` 才会关闭。

### `task_periodic[].cron`

- cron 表达式，支持 5 段分钟级表达式、6 段秒级表达式和 `@every` 描述符。
- 5 段表达式示例：`*/5 * * * *`，表示每 5 分钟触发一次。
- 6 段秒级表达式示例：`*/10 * * * * *`，第一段是秒，表示每 10 秒触发一次。
- 任何 cron 相邻两次触发间隔都不能小于 `5` 秒，避免秒字段绕过固定间隔保护。
- `cron` 和 `every_seconds` 只能配置一个；如果只是固定秒级间隔，优先使用 `every_seconds`，可读性更高。

### `task_periodic[].every_seconds`

- 固定秒级间隔，配置后会转换成 `@every Ns` 交给调度器执行。
- 最小值为 `5`，低于该值会跳过当前周期任务，避免误配置造成队列压力。
- 示例：`every_seconds: 10` 表示每 10 秒触发一次；不要在该字段填写 `*/10 * * * * *`，这种 6 段表达式应填写到 `cron`。

### `task_periodic[].workflow`

- 触发的工作流名称。

### `task_periodic[].queue`

- 投递队列名。

### `task_periodic[].targets`

- 工作流目标列表。
- 含义由具体业务定义。

### `task_periodic[].shard_total`

- 任务分片总数，最大 `128`。

### `task_periodic[].gray_percent`

- 工作流节点声明支持灰度时，按 `workflow_id + node + shard_index` 稳定哈希筛选需要执行的分片，范围 `0~100`。
- 未声明支持灰度的工作流节点会执行全部分片，该字段不会生效；默认运行配置中不需要为 order、归档、用户标签任务填写。

### `task_periodic[].retry`

- 覆盖默认重试次数，范围 `0~25`。

### `task_periodic[].timeout_seconds`

- 覆盖工作流节点超时时间，单位秒，范围 `0~86400`。
- 默认运行配置不填写该字段，优先使用各工作流节点在代码中定义的业务超时；只有确实要统一覆盖所有节点超时时才配置。

### `task_periodic[].deadline`

- 可选任务截止时间，必须使用 RFC3339 格式；超过该时间后任务不会继续执行。

### `task_periodic[].unique_key`

- 周期任务唯一键。

### `task_periodic[].unique_ttl_seconds`

- 周期任务唯一键 TTL，单位秒，最大 `2592000`（30 天）。

## 运行配置来源 `runtime_config`

`runtime_config` 只控制会随业务增长的大列表运行配置来源。基础设施配置仍从启动 YAML 读取。

### `runtime_config.source`

- 支持 `file`、`database`；省略时默认 `file`，当前样例显式配置为 `database`。
- `file`：继续从 `config_files.runtime` 指向的 YAML 读取 `task_periodic` 和 `archive_jobs`。
- `database`：启动时读取 `runtime_config_state` 指向的 active release 快照；没有已发布版本时优先发布迁移种下的草稿表，草稿为空再导入当前文件大列表并发布初始版本。
- 后续变更必须通过后台“运行配置”页面保存草稿并发布，不再人工修改运行期文件的大列表段。

### `runtime_config.poll_interval_seconds`

- DB 模式下实例轻量轮询 active 版本的间隔秒数，默认 `30`，最小 `5`。
- 轮询只读取 table-cache 的 `runtime_config:state`；版本未变化时不读取发布快照和明细表。

## 外部告警配置 `alert`

这组配置用于把后台任务终态失败、周期任务配置异常和任务系统运行异常等需要人工介入的问题推送到外部群告警。当前支持 Lark 群机器人。

### `alert.lark.enabled`

- 是否启用 Lark 群机器人告警。
- Collector、配置热加载和服务生命周期等运行告警独立于任务系统注册，`task.enabled=false` 时仍会发送；任务终态和周期调度类告警只在任务系统启用时产生。
- 启用后，异步任务、周期触发任务和工作流节点进入终态失败时会发送 Lark 卡片告警；中间重试失败不会发送。
- 周期任务配置异常会在启动期校验和调度同步时发送 Lark 卡片告警；同一条异常配置默认按 5 分钟窗口限频推送，窗口内重复触发会计入下一次告警的触发次数，避免同步循环重复刷屏。
- 周期调度同步、cron 注册、leader 校验、队列巡检、周期入队、归档任务配置异常和 archived 过期清理等任务系统运行异常也会发送 Lark 卡片告警；同一异常指纹默认按 5 分钟窗口合并，队列积压超限这类主动保护性跳过不会按 P1 推送。
- Collector 后台消费、缓存异步刷新投递、Excel 异步导出、配置热加载和服务启动/平滑停止这类不一定会直接返回给操作者的后台失败，也会复用同一条运行异常告警链路；事件 ID、jobId、cache key 等高基数字段只进入错误摘要，不进入告警指纹，避免故障时刷屏。
- `task_periodic[].workflow=task_report.daily_summary` 会按当前周期任务调度时间发送周期任务与工作流运行日报卡片，默认以本轮计划触发时间为窗口终点，从 `task_workflow_run` 和 `task_failure` 的有界时间窗口聚合工作流、失败、慢任务与当前队列状态。
- 默认种子每天 10 点触发；如手动调整调度时间，日报窗口跟随新的计划触发时间。手动触发未携带计划时间时，按实际执行时间回看 24 小时。
- Asynq 终态时间精度为秒；默认窗口会自动按整秒对齐，手工覆盖的 `windowStart/windowEnd` 也必须使用整秒 RFC3339，避免相邻窗口边界漏计或重复。
- 日报不再扫描 Redis completed/archived；成功任务热状态按 `task.completed_retention_seconds` 短留，最终失败任务仍按 `task.archived_retention_seconds` 支持人工重跑。
- 数据库聚合只读取有索引的日报时间窗口，各维度结果和失败/慢任务明细均有固定上限；历史清理按主键小批量执行，避免日报和清理制造新的数据库压力。

### `alert.lark.webhook_url`

- Lark 群机器人 webhook URL，仅支持 `http`/`https`。
- 为空时读取 `alert.lark.webhook_url_ref` 指向的文件。

### `alert.lark.webhook_url_ref`

- Lark 群机器人 webhook URL 文件路径。

### `alert.lark.secret`

- Lark 群机器人签名密钥。
- 为空时读取 `alert.lark.secret_ref` 指向的文件。

### `alert.lark.secret_ref`

- Lark 群机器人签名密钥文件路径。

### `alert.lark.timeout_seconds`

- Lark HTTP 请求超时时间，单位秒。
- 默认 `5`，最大 `30`。

### `alert.lark.at_all`

- 是否在告警中 @所有人。
- 生产建议谨慎开启，避免频繁打扰。

### `alert.lark.max_error_bytes`

- 错误摘要最大字节数。
- 默认 `800`，超出后按 UTF-8 安全截断。

### 本地真实发送验证

本地可通过受环境变量保护的 live smoke test 验证真实 Lark 群机器人链路：

```bash
ADMIN_LARK_LIVE=1 \
ADMIN_LARK_WEBHOOK_URL='https://open.feishu.cn/open-apis/bot/v2/hook/xxx' \
ADMIN_LARK_SECRET='可选签名密钥' \

```

- 未设置 `ADMIN_LARK_LIVE=1` 时测试会跳过，避免日常测试误发群消息。
- `ADMIN_LARK_AT_ALL=true` 时会在测试消息中 @所有人，默认不启用。
