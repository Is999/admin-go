本文是 Admin 与前台 API 接口契约的导航入口，面向前端、测试、后端联调和运维人员。接口按调用任务和后台菜单拆分：本页负责选择正确文档，子文档负责完整请求、响应、安全字段、业务码、示例和失败处理。

> 开始联调前先阅读[接口文档统一规范](接口文档/接口文档统一规范.md)。接口文档与代码冲突时不能直接任选其一，应以 RouteSpecs、types、业务码和安全清单核对后修正文档或实现。

## 3. 访问边界

| 边界 | 调用方 | 核心要求 |
| --- | --- | --- |
| 后台公网接口 | 已登录管理员 | JWT、Redis session 和权限为基础要求；RouteMeta/接口文档标记为敏感操作时必须额外提交有效 MFA ticket；签名/加密字段严格按 RouteSecurityPolicy 执行 |
| 公开探针 | LB/监控 | 不要求 JWT；依赖网络和部署白名单，默认 access log 降噪 |
| Admin 内网接口 | 运维或受信任服务 | 独立 internal listener、私网来源、Ops HMAC、timestamp、Redis nonce，跨主机 mTLS |
| API 内网接口 | Admin 服务 | API 独立 internal listener 和相同级别的 Ops 防护 |
| 文档正文 | 已登录管理员 | 入口路由权限 + `site/path` 精确文档权限 |

前端不能因为页面隐藏就省略后端权限，也不能把内网接口当作“免鉴权公网接口”。

## 4. 统一响应与 Trace

```json
{
  "status": true,
  "code": 1,
  "message": "成功",
  "data": {},
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "spanId": "00f067aa0ba902b7"
}
```

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `status` | bool | 业务是否成功，不能只根据 HTTP 2xx 推断 |
| `code` | int | 稳定业务码，调用方按码处理 |
| `message` | string | 按语言环境返回的人读文案，不作为程序分支 |
| `data` | object/array/null | 当前接口数据，以子文档为准 |
| `traceId` | string | 关联请求、日志、审计和 Trace |
| `spanId` | string | 定位当前处理片段 |

提交缺陷时至少保留环境、时间、method/path、请求参数脱敏快照、HTTP 状态、业务码和 `traceId`。

## 5. 常用公共约束

- 时间统一写明 RFC3339、Unix 秒/毫秒或业务时区，不能只写“时间戳”。
- UID、雪花 ID 等大整数用十进制字符串传输，避免 JavaScript 精度损失。
- 列表接口必须说明 page/pageSize 上限、排序、筛选和空列表语义。
- `processAt` 与 `processInSeconds` 等互斥字段不能同时发送。
- 重试、超时、TTL、批次和分片必须满足子文档上限；前端校验不替代服务端校验。
- 请求/响应签名与加密只覆盖安全字段表声明的点路径，未知字段不得自动加入。
- 提交类接口发生超时后先按幂等键或查询接口确认结果，不能无条件重复提交。

## 6. 契约变更流程

接口发生 method/path、字段、业务码、权限、MFA、签名/加密或访问边界变化时，必须同步：

1. types 与 Validate。
2. RouteSpecs、RouteMeta、权限和审计动作。
3. RouteSecurityPolicy 与安全清单。
4. 业务码、HTTP 映射和 i18n。
5. 本站字段级接口文档和示例。
6. 前端 API wrapper、TypeScript 类型、权限码和多语言。
7. 契约测试、前后端测试与联调证据。

只更新概览页或只更新代码都不构成完整交付。
