# 标准开发流程

把本 skill 作为主流程；按当前任务真实技术面调用专项 skill，不替代专项领域规则。

## 表达闸门

计划、实现说明、审查结论和交付记录不得用“简洁”“闭环”“同步相关内容”“必要时”“验证通过”“生产可用”等词代替动作和证据：

- 每项规则必须能回答何时触发、检查什么、执行什么、怎样判定通过、失败后怎样处理。
- 每项完成结论必须能对应到需求项、生产入口、实现文件、最终副作用、同步面和最后一次修改后的验证。
- 无法给出触发条件的“必要时/按需”、无法列出对象的“相关内容”、无法给出命令与结果的“验证通过”均视为未执行。

## 阶段闸门

1. 判断请求类型：分析、实现、审查、验证或交接。意图或边界不清时使用 `$requirement-intent-gate`，暂停编辑。
2. 读取从工作区到目标目录生效的 `AGENTS.md`，并用 `rg --files` 发现真实代码、测试、配置、契约和文档入口。
3. 非平凡任务先说明目标行为、源码证据、拟改文件、明确非目标、风险面和验证命令。
4. 选择最小实现。优先沿用现有分层、注册点和成熟依赖；新增抽象、目录、框架或依赖前，说明必要性、替代方案、影响范围和验证方式，并取得确认。
5. 任务触及项目自有 YAML 时，为每个新增或修改的固定字段核对 config struct/tag、默认值、normalize/getter、校验器、消费方和 reload 应用器；在字段正上方补同缩进中文注释，写明真实用途与已存在的取值、空值、生效和安全约束。父节点不能代替子字段，动态 map 和第三方 schema 按 `$go-config-runtime-guard` 的条件记录处理或排除证据。
6. 只在任务触及 SQL 时启用 SQL 闸门：先区分完整初始化资产、运行时代码 SQL 和存量库一次性变更。优先 GORM 链式调用；原生 SQL 说明例外原因、索引、扫描范围、分页或批量、超时、并发和 DB 压力。
7. DDL/DML 变化直接更新仓库原始初始化基线，不新增碎片化迁移 SQL 或日常迁移版本；存量库 SQL 只放被忽略的 `data/sql-changes/<change-id>/`，交给 DBA/运维执行并确认未进入 Git。
8. 按源码变化和调用方搜索识别触发面，并建立同步影响记录。将 route、request/response、RouteMeta、权限/安全、业务码/i18n、配置、Model、完整初始化 DDL/DML、SQL/Lua、Redis Key、前端 wrapper/type、文档、测试和运维步骤作为发现清单，而不是固定填空表；每个被触发面记录源码依据、修改文件、验证结果和未覆盖路径。只有常见风险面容易被误判为已处理时才记录不适用及具体依据，禁止用一个“不适用”概括所有未检查项。
9. 按真实技术面调用专项 skill。Redis、配置、worker、安全路由、数据库变更、前端或兄弟仓库不存在时，不强行套用。
10. 持续复核每个新增目录、接口、结构体、状态、分支、wrapper 和 helper：必须存在当前需求、真实调用方、稳定复用边界或故障证据；只转发参数且无校验、转换、事务、重试或依赖隔离职责的包装应内联。清理现有文件时先区分生产已启用、基础能力但当前未启用、确认废弃无用；没有业务调用方不能单独作为删除依据，稳定扩展契约、已有多实现、外部依赖隔离、共享约定和 CLI/Make/测试/运维能力必须保留并准确标注启用状态。优化或重构使用 `$simple-code-guard`。
11. 最终复核前冻结编辑，确认候选版本位于 worktree 还是 index。最后一次修改会使受影响的旧验证失效，必须重跑。
12. 非平凡交付使用 `$implementation-closure-review`；涉及暂存或运维交接时使用 `$release-handoff-guard`。

## 必留证据

- 源码事实：已检查的入口、调用链、配置、文档、SQL、日志或测试。
- 实现边界：修改内容、非目标和已确认假设。
- 同步面：按源码识别并实际处理的代码、契约、数据、配置、前端、文档与运维面；常见风险面若判定不适用，附调用方搜索或注册/配置依据。
- 验证快照：命令、结果、worktree/index 状态、跳过原因和剩余风险。
- 仓库状态：每个触达仓库的 `git diff --check`、`git diff --cached --check`（存在 staged 文件时）和 `git status --short`。

## 完成判定

- `已完成且已验证`：所有需求项有真实入口、完整调用链、成功/失败终态和同步影响记录；记录中按 Go、前端、配置、SQL、文档和 Skill 实际触达面列出的命令，均在最后一次修改后执行且退出码为 `0`。
- `已完成但未验证`：实现与同步已完成，但明确命令因环境或权限未执行；必须列出未覆盖风险和补跑责任。
- `已交付待人工执行`：代码或本地 DBA/运维材料已准备，但生产 SQL、发布、缓存清理或重启仍需授权人员执行；不得写成已上线。
- `已跳过`：该面不存在或经源码证明不受影响；必须记录证据，不能用“无需处理”一句带过。
- `被阻塞`：缺少会实质改变实现的需求选择、权限、依赖或环境；说明已检查证据、影响和解除条件。

## 交付

最终说明区分已完成、已验证、已跳过、被阻塞和后续事项，并明确是否需要迁移、回填、缓存失效、重启、回滚或补偿。

大型任务需要结构化交接时，读取 `references/delivery-template.md`。
